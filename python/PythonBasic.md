# Основы Python

## 1. Чем list отличается от tuple?

Оба — последовательности, но главное отличие — **изменяемость**.

```python
lst = [1, 2, 3]
tpl = (1, 2, 3)

lst.append(4)  # ✅ можно
tpl.append(4)  # ❌ AttributeError: у tuple нет append
```

| | `list` | `tuple` |
|---|---|---|
| Изменяемость | mutable | immutable |
| Синтаксис | `[1, 2, 3]` | `(1, 2, 3)` |
| Можно использовать как ключ `dict` | ❌ | ✅ (если элементы хешируемы) |
| Производительность | медленнее, динамический массив | чуть быстрее, фиксированный размер |
| Назначение | однородная коллекция, которая меняется | запись фиксированного набора, гетерогенные данные |

Отсюда ключевое следствие: `tuple` можно использовать как ключ словаря или элемент `set`,
потому что он хешируем.

```python
d = {(1, 2): "point"}   # ✅
d = {[1, 2]: "point"}   # ❌ TypeError: unhashable type
```

### Если совсем коротко

- `list` — изменяемый, `tuple` — неизменяемый.
- Неизменяемость делает `tuple` хешируемым и чуть более быстрым.

## 2. Что такое mutable и immutable типы?

Неизменяемые (immutable) объекты нельзя изменить после создания — любая «операция
изменения» создаёт новый объект.

**Immutable:** `int`, `float`, `str`, `tuple`, `frozenset`, `bytes`, `bool`.

**Mutable:** `list`, `dict`, `set`, `bytearray`.

```python
s = "hello"
s += " world"
# "hello" остался в памяти, создана новая строка "hello world"
```

```python
a = 1
print(id(a))   # например 1400000000
a += 1
print(id(a))   # другой id — это уже новый объект int
```

Почему это важно:

1. **Хешируемость** — только immutable объекты могут быть ключами `dict`/элементами `set`.
2. **Поведение при передаче** — mutable объект, переданный в функцию, может быть изменён
   «снаружи», а immutable — нет (его просто невозможно изменить).
3. **Aliasing** — две переменные могут ссылаться на один mutable объект:

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)   # [1, 2, 3, 4] — a тоже изменился!
```

## 3. Чем оператор is отличается от ==

- `==` проверяет **равенство по значению** (вызывает `__eq__`).
- `is` проверяет **идентичность** — указывают ли обе переменные на один и тот же объект
  (сравнивает `id()`).

```python
a = [1, 2, 3]
b = [1, 2, 3]

a == b   # True  — содержимое одинаково
a is b   # False — это разные объекты

c = a
a is c   # True  — один и тот же объект
```

Классическая ловушка — сравнение с `None`:

```python
x == None   # ❌ плохо: может переопределён __eq__
x is None   # ✅ правильно
```

Ещё один нюанс — интернирование маленьких целых и строк:

```python
a = 256
b = 256
a is b   # True  — интернирование

x = 1000
y = 1000
x is y   # False (зависит от реализации) — не полагайтесь на это!
```

Правило: используйте `is` только для сравнения с синглтонами (`None`, `True`, `False`)
и когда действительно нужна проверка идентичности.

## 4. Что такое args и kwargs?

`*args` собирает произвольное число **позиционных** аргументов в кортеж, а `**kwargs` —
произвольное число **именованных** аргументов в словарь.

```python
def foo(*args, **kwargs):
    print(args)    # (1, 2, 3)
    print(kwargs)  # {'a': 10, 'b': 20}

foo(1, 2, 3, a=10, b=20)
```

Обратная операция — **распаковка**:

```python
def add(a, b):
    return a + b

nums = [1, 2]
add(*nums)             # add(1, 2)

params = {'a': 1, 'b': 2}
add(**params)          # add(a=1, b=2)
```

Порядок в сигнатуре фиксирован:

```python
def f(a, b, *args, c=0, **kwargs):
    ...
```

- обычные позиционные;
- `*args`;
- именованные со значениями по умолчанию (keyword-only);
- `**kwargs`.

## 5. Что такое итератор и итерируемый объект?

**Итерируемый объект (iterable)** — то, что можно обойти циклом. У него есть метод
`__iter__()`, возвращающий итератор.

**Итератор (iterator)** — объект с методом `__next__()`, который отдаёт элементы по
одному и бросает `StopIteration`, когда они закончились.

```python
lst = [1, 2, 3]        # iterable
it = iter(lst)         # iterator

next(it)   # 1
next(it)   # 2
next(it)   # 3
next(it)   # StopIteration
```

Важно: итератор «одноразовый» — после исчерпания повторно пройти по нему нельзя.

```python
it = iter([1, 2, 3])
list(it)   # [1, 2, 3]
list(it)   # [] — уже пусто
```

Ленивые итераторы можно создавать генераторами (см. раздел про `yield`):

```python
def gen():
    yield 1
    yield 2

g = gen()
next(g)   # 1
```

## 6. Почему изменяемый объект нельзя использовать как значение по умолчанию?

Значения по умолчанию вычисляются **один раз, в момент определения функции**, а не при
каждом вызове. Поэтому mutable-объект «переживает» между вызовами.

```python
def add_item(item, items=[]):
    items.append(item)
    return items

add_item(1)   # [1]
add_item(2)   # [1, 2]  ← неожиданно!
```

Правильный подход — `None` + создание внутри:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

add_item(1)   # [1]
add_item(2)   # [2]  ✅
```

## 7. Что такое срезы slicing?

Срез позволяет получить часть последовательности: `seq[start:stop:step]`.

```python
lst = [0, 1, 2, 3, 4, 5]

lst[1:4]      # [1, 2, 3]
lst[:3]       # [0, 1, 2]
lst[3:]       # [3, 4, 5]
lst[::2]      # [0, 2, 4]
lst[::-1]     # [5, 4, 3, 2, 1, 0] — разворот
```

Срез создаёт **новый объект** (мелкую копию), исходный не меняется.

Срез работает на строках, списках, кортежах и любых объектах с `__getitem__`.

```python
s = "hello"
s[1:3]   # 'el'
```

## 8. Как работает контекстный менеджер with?

`with` гарантирует выполнение завершающего кода (освобождение ресурсов) даже при
исключении. Реализуется методами `__enter__` и `__exit__`.

```python
class Resource:
    def __enter__(self):
        print("открыть")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("закрыть")
        return False   # не подавляем исключение

with Resource() as r:
    print("работаем")
# открыть
# работаем
# закрыть
```

Чаще всего используют готовые менеджеры — например `open`:

```python
with open("file.txt") as f:
    data = f.read()
# файл гарантированно закрыт
```

`__exit__` получает тип исключения, само исключение и traceback. Если вернуть `True`,
исключение будет подавлено (редко нужно).

## 9. Что такое global и nonlocal?

`global` — обращение к переменной модульного уровня внутри функции.

```python
x = 0

def inc():
    global x
    x += 1

inc()
print(x)   # 1
```

Без `global` выражение `x += 1` попыталось бы создать локальную переменную и упало бы
с `UnboundLocalError`.

`nonlocal` — обращение к переменной из **ближайшей внешней (объемлющей) функции**,
но не из глобальной области. Нужно для замыканий:

```python
def counter():
    count = 0
    def inner():
        nonlocal count
        count += 1
        return count
    return inner

c = counter()
c()   # 1
c()   # 2
```

## 10. Способы форматирования строк: f-string, format, %

Три основных способа, от старого к новому:

```python
name = "Alice"
age = 30

# 1. %-форматирование (старый стиль)
"Имя: %s, возраст: %d" % (name, age)

# 2. str.format
"Имя: {}, возраст: {}".format(name, age)

# 3. f-string (Python 3.6+)
f"Имя: {name}, возраст: {age}"
```

`f-string` — самый читаемый и быстрый, в него можно вставлять выражения:

```python
f"2 + 2 = {2 + 2}"
f"{name=}"            # name='Alice'
f"{age:03d}"          # '030' — форматирование
```

Когда использовать `format` вместо f-string: когда шаблон формируется динамически или
хранится отдельно от данных (например, в конфиге), а подстановку делаем позже.
