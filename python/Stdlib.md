# Стандартная библиотека и структуры данных

## 1. Как устроены list, dict, set, tuple?

| Тип | Внутри | Упорядоченность | Дубликаты | Изменяемость |
|---|---|---|---|---|
| `list` | динамический массив указателей | ✅ | ✅ | mutable |
| `tuple` | неизменяемый массив указателей | ✅ | ✅ | immutable |
| `dict` | хеш-таблица | ✅ (с 3.7) | ключи уникальны | mutable |
| `set` | хеш-таблица | ❌ | уникальны | mutable |

```python
lst = [1, 2, 3]           # list
tpl = (1, 2, 3)           # tuple
dct = {"a": 1, "b": 2}    # dict
st = {1, 2, 3}            # set
```

Ключевые различия:

- `list` — упорядоченная изменяемая последовательность, доступ по индексу O(1).
- `tuple` — то же, но неизменяемая; поэтому хешируемая.
- `dict` — отображение ключ → значение; ключи должны быть хешируемыми.
- `set` — неупорядоченная коллекция уникальных хешируемых элементов.

```python
d = {"a": 1}
d[1] = 2        # ❌ int можно, но...
d[[1]] = 2      # ❌ list нехешируем

s = {1, 2, 2}   # {1, 2} — дубликаты убираются
```

## 2. Какова сложность основных операций?

| Операция | `list` | `dict`/`set` |
|---|---|---|
| доступ по индексу/ключу | O(1) | O(1) в среднем |
| поиск значения | O(n) | O(1) в среднем |
| вставка в конец | O(1) амортизированно | O(1) в среднем |
| вставка в начало/середину | O(n) | — |
| удаление | O(n) | O(1) в среднем |
| `in` (проверка наличия) | O(n) | O(1) в среднем |

Пример, почему это важно:

```python
nums = list(range(10_000_000))

# плохо: O(n) на каждую проверку
if target in nums: ...

# хорошо: O(1) в среднем
s = set(nums)
if target in s: ...
```

Для `dict`/`set` худший случай — O(n) при коллизиях хешей, но в среднем O(1).

## 3. Как работает dict изнутри?

`dict` — это хеш-таблица. Алгоритм:

1. Вычисляется `hash(key)`.
2. Хеш преобразуется в индекс корзины (bucket).
3. В корзине хранится ссылка на `(key, value)`.
4. При коллизии используются техники разрешения (open addressing).

```text
key
 ↓
hash(key)
 ↓
bucket index
 ↓
(ключ, значение)
```

Требование: ключ должен быть **хешируемым** — реализовывать `__hash__` и быть
неизменяемым (значение хеша не должно меняться в течение жизни объекта).

```python
hash("hello")   # какой-то int
hash([1, 2])    # ❌ TypeError: unhashable type
```

Следствие: `dict` жертвует порядком и компактностью ради быстрого поиска O(1). Порядок
вставки при этом сохраняется (реализация в CPython 3.7+), но полагаться на «сортировку»
нельзя.

## 4. Что полезного есть в модуле collections?

| Контейнер | Что делает |
|---|---|
| `defaultdict` | словарь со значением по умолчанию |
| `Counter` | подсчёт частоты элементов |
| `deque` | двусторонняя очередь, O(1) с обоих концов |
| `OrderedDict` | словарь, помнящий порядок вставки (и методы `move_to_end`) |
| `namedtuple` | именованный кортеж |
| `ChainMap` | объединение нескольких словарей |

```python
from collections import defaultdict, Counter, deque, namedtuple

# defaultdict — не падает при отсутствии ключа
d = defaultdict(list)
d["a"].append(1)      # ✅ ключ "a" создаётся сам

# Counter — подсчёт
c = Counter("abracadabra")
c.most_common(2)      # [('a', 5), ('b', 2)]

# deque — быстрое добавление с обоих концов
dq = deque([1, 2, 3])
dq.appendleft(0)
dq.popleft()          # 0

# namedtuple — именованный кортеж
Point = namedtuple("Point", ["x", "y"])
p = Point(1, 2)
p.x, p.y              # 1, 2
```

`deque` особенно полезен для очередей и стека, где `list.pop(0)` был бы O(n).

## 5. Чем list comprehension отличается от generator expression?

Оба записываются похоже, но ведут себя по-разному.

**List comprehension** — создаёт список целиком в памяти сразу.

```python
squares = [x * x for x in range(10)]
# [0, 1, 4, 9, ...] — готовый list
```

**Generator expression** — ленивый итератор, вычисляет элементы по одному по мере
запроса.

```python
squares = (x * x for x in range(10))
next(squares)   # 0
next(squares)   # 1
```

Отличия:

| | list comprehension | generator expression |
|---|---|---|
| Скобки | `[...]` | `(...)` (или без скобок в вызове функции) |
| Память | весь список сразу | O(1), по одному элементу |
| Перебор | сколько угодно раз | один раз |
| Применение | когда нужен список | когда нужна ленивость / поток |

```python
sum(x * x for x in range(10))   # generator — экономия памяти
sum([x * x for x in range(10)]) # list — промежуточный список
```

## 6. Что даёт модуль functools?

| Инструмент | Что делает |
|---|---|
| `lru_cache` | мемоизация результатов функции |
| `partial` | фиксация части аргументов |
| `reduce` | свёртка последовательности |
| `total_ordering` | генерация всех операторов сравнения по `__eq__` + `__lt__` |
| `wraps` | сохранение метаданных при написании декораторов |
| `singledispatch` | перегрузка функции по типу первого аргумента |

```python
from functools import lru_cache, partial, reduce

@lru_cache(maxsize=128)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

fib(100)   # быстро благодаря кешу

def power(base, exp):
    return base ** exp

square = partial(power, exp=2)
square(5)   # 25

reduce(lambda a, b: a * b, [1, 2, 3, 4])   # 24
```

`wraps` важен при создании собственных декораторов — он сохраняет `__name__`,
`__doc__` и прочие атрибуты оборачиваемой функции (см. раздел про декораторы).

## 7. Как работают enumerate, zip, map, filter?

Это встроенные средства работы с последовательностями. Все они возвращают **итераторы**
(ленивые).

```python
# enumerate — индекс + элемент
for i, item in enumerate(["a", "b", "c"]):
    print(i, item)   # 0 a / 1 b / 2 c

# zip — параллельно по нескольким итераторам
list(zip([1, 2, 3], ["a", "b"]))   # [(1, 'a'), (2, 'b')]

# map — применить функцию к каждому элементу
list(map(str.upper, ["a", "b"]))   # ['A', 'B']

# filter — оставить подходящие элементы
list(filter(lambda x: x > 2, [1, 2, 3, 4]))   # [3, 4]
```

Особенности:

- `zip` обрезается по самому короткому итератору (используйте `itertools.zip_longest`
  для заполнения недостающего).
- `map`/`filter` с лямбдой часто заменяют на comprehension — читабельнее:

```python
[x * 2 for x in range(5)]                  # вместо map
[x for x in range(5) if x > 2]             # вместо filter
```
